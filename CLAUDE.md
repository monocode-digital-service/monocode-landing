# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

pnpm monorepo for the Monocode marketing site (one landing page plus two legal pages, pt-BR): `apps/web` (Next.js 16) plus a shared shadcn/ui package (`packages/ui`). No backend, database, auth, or API layer. Deployed to Vercel. Default branch is `main`.

Design source: Figma file `oCXHJvibR4m9o9jwvip5LT`, page "3. Site" (node `118:471`). Copy and brand rules come from `../monocode-brand/docs/` (`monocode-site.md`, `monocode-marca.md`). Copy rules: no em dash, no promises of deadline or result, no emoji, no IoT in public messaging, no status or progress wording (em construção, disponível, feito, rodando: the site sells to a business owner and must not read as unfinished), and "automação" (runs on a rule the team defined) is never mixed with "agente" (reads context and decides). Don't repeat "a Monocode" in every sentence. Monocode Operations and Monocode Growth are the company's two fronts and appear with equal weight. Site copy and `../monocode-brand/docs/monocode-site.md` change together (that folder is not a git repo).

**Next.js 16 has breaking changes vs. training data.** Before writing Next.js code, read the relevant guide in `apps/web/node_modules/next/dist/docs/` (see `apps/web/AGENTS.md`, which `next dev` regenerates).

## Commands

Run from repo root:

- `pnpm dev` / `pnpm dev:web` — dev server on http://localhost:3001
- `pnpm build` — build all workspaces
- `pnpm check-types` — `tsc --noEmit` in every workspace
- `pnpm check` — Biome lint + format, **writes fixes**
- `pnpm env:generate` — regenerate `apps/web/src/env.ts` after editing `apps/web/.env.schema` (also runs on `postinstall`)
- `pnpm deploy:check` / `pnpm deploy` / `pnpm deploy:prod` — Vercel dry-run / preview / production

- OG image: `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --hide-scrollbars --window-size=1200,630 --virtual-time-budget=5000 --screenshot=apps/web/src/app/opengraph-image.png "file://$PWD/design/og/og.html"` after editing `design/og/og.html`
- `pnpm --filter web exec next typegen` — regenerate typed routes after adding a route (`typedRoutes` is on; `next dev` and `next build` also do it)

No test framework is configured.

## Architecture

- **Page composition** — `apps/web/src/app/page.tsx` stacks one component per section from `components/sections/`. Shared brand pieces live in `components/brand/`, header/footer in `components/layout/`. The header (`site-header.tsx`) is fixed and mounted once in `layout.tsx`: transparent at the top of the page (over the hero, or over the dark band of the legal pages, lime logo and light menu) and, after scrolling, a floating capsule of light frosted glass (translucent paper tint, strong backdrop blur), a little wider than the content column, with logo, menu and button in `ink` (the button turns dark because `lime` never goes on a light surface). The capsule appears around the logo and the menu where they already are (same height, edges at `--pad-l` / `--pad-r` from them) and only then narrows to `--cap-w`, while the logo and the menu slide inward by transform with the same duration and easing, so their distance to the capsule edges never changes; nothing moves vertically. The geometry comes from the `--row-x` / `--cap-x` / `--inset` variables in container units. Menu colours come from `--nav-fg` / `--nav-accent`, and the button from `--primary`, all switched on the header; the mobile menu panel resets `--primary` because it is always dark. The inline boot script in `layout.tsx` (it also adds the `js` class) sets `data-scrolled` and `data-scrolled-far` on `<html>` before the first paint and keeps them updated, and the CSS reacts through the `in-data-scrolled:` / `in-data-scrolled-far:` variants (no re-render); the back-to-top button (`back-to-top.tsx`) uses the second one. Without JavaScript the header is `absolute` instead of fixed (`in-[.js]:fixed`), so it leaves with the first block instead of sitting transparent over the light sections. Every route needs a dark block behind the header at the top: the hero, the band of the legal pages, or the one in `app/not-found.tsx` (the 404 page, which renders inside the layout). Contact data (WhatsApp, email, LinkedIn, Instagram, CNPJ) is centralized in `src/lib/site.ts`; every CTA uses `WhatsAppButton`. The menu item "Soluções" points to `#o-que-muda`, the start of the solutions block.
- **Situations** — the "O que muda quando a IA entra" section (`sections/situations.tsx`) is data-driven from `src/lib/situations.ts`: the two fronts as tabs, and per front a list of situations with the steps of what starts to happen. The interactive part is the client component `sections/situations-explorer.tsx`; the steps show in a side panel on desktop and open under the tapped situation on mobile. The selected front and the selected situation are marked by a dark box that slides between items (transform only: the list box uses `translateY` plus `scaleY` over a fixed reference height, measured from the selected row; on mobile the row keeps its own background because the steps open right under it). On mobile the steps of the previous situation close when another opens, so the component scrolls by the difference to keep the tapped row where it was. The concrete day-to-day scenes live here, so Soluções keeps each piece to a couple of lines.
- **Backgrounds** — `components/backgrounds/` holds the vendored React Bits Topography (hero, via `ogl`/WebGL); the closing block uses the static `bg-hatch-lime` utility instead of a canvas. Biome linting is disabled for that folder (`biome.json` override); keep upstream code as-is, except the marked Topography aspect fix. `HeroBackground` (`components/layout/backgrounds.tsx`) only mounts it when WebGL 2 is available: without it the vendored code throws and the whole page falls to the error screen.
- **Hairline figures** — the animated isometric illustrations in Soluções and Como trabalhamos. Sources live in `design/hairline/*.js` (format of the `hairline-create` skill: build, validate and look there). `node design/hairline/export.mjs` copies the kernel and figures as ES modules into `apps/web/src/components/hairline/figures/` (generated, excluded from Biome); `HairlineFigure` mounts one with a `light` or `dark` palette set through the `--hairline-*` CSS variables and applies the "Volume" treatment on top of the engine, without touching the kernel: gradient fills are injected inside each SVG (`<defs>` plus a `<style>`, because `url(#id)` in an external stylesheet is not document-local in every browser) and the first solid a figure draws is treated as its base; stroke widths live in `packages/ui/src/styles/globals.css` and follow the figure width (`cqw` with a floor), since the engine uses non-scaling strokes. `export.mjs` reads the kernel from `.claude/skills/hairline-create/`; when that folder is missing, generate a figure module by applying the same three replaces by hand (as was done for `evolucao`). `node design/hairline/preview.mjs <figs> "<preset>" <out>.html` builds a palette/stroke preview page.
- **Motion** — entrance animations are GSAP (`gsap`, `@gsap/react`; ScrollTrigger, SplitText and DrawSVG are free since 3.13) wired by data attributes, all handled in `components/layout/site-motion.tsx` (mounted once in `layout.tsx`, and set up again on every route change: Next swaps pages without a reload, and without that the elements of the incoming page stay hidden): `data-reveal="lines"` (title lines rise behind a mask), `"up"`, `"scale"`, `"wipe"` (photo), `"draw"` (inline SVG stroke, see `brand/wordmark-outline.tsx`) and `data-parallax`. `globals.css` hides `[data-reveal]` only under `html.js` (set by the inline script in `layout.tsx`) and keeps everything visible under `prefers-reduced-motion`. Animate only opacity, transform and clip-path; every reveal runs once. The one exception is the header capsule, which animates `left` / `right` on a single absolutely positioned layer so that its border and radius do not deform. `SiteMotion` also calls `ScrollTrigger.refresh()` when the page height changes (front switch, steps opening on mobile, fonts and figures loading): triggers store positions, and without the refresh the sections below would reveal late. To animate a new element, add the attribute; sections stay Server Components.
- **Scroll and waves** — Lenis smooth scroll is mounted in `layout.tsx` (`components/layout/smooth-scroll.tsx`; menu anchors use an eased duration). The same file cancels the browser's native jump on same-page anchor clicks (Lenis animates but does not `preventDefault`): without that, the page jumps to the anchor for one frame, the hero parallax takes its final offset and the hero text flashes at the top. Dark blocks bend their edges with scroll velocity via `components/brand/wave-background. It then redoes by hand what the jump would also do: the `#` in the address (without stacking a repeated entry in the history) and moving focus to the target section, which gets `tabindex='-1'` and no focus outline.tsx` (`WaveBackground` layer, `WaveBottomEdge` for the hero, size from the `--bend` CSS var). Both are off under `prefers-reduced-motion`.
- **SEO** — `site.url`, `site.title` and `site.description` in `src/lib/site.ts` feed the root `metadata` (canonical, Open Graph), `app/robots.ts`, `app/sitemap.ts` and the JSON-LD graph in `src/lib/json-ld.ts` (Organization, WebSite, founder, projects), rendered by `page.tsx`. The canonical host is `https://www.monocode.com.br`. The primary keyword is "agentes de IA para empresas" with the São Paulo modifier; the H1 stays the brand headline. `app/opengraph-image.png` is a screenshot of `design/og/og.html` (see OG image below). A new route needs an entry in `sitemap.ts` and exports its metadata through `pageMetadata` (`src/lib/metadata.ts`), which sets the title, description, canonical and the page's own Open Graph (metadata merges shallowly: a page that sets `openGraph` replaces the layout's whole object and loses the file-based image, so the helper repeats the shared fields and declares the image; its alt text and `app/opengraph-image.alt.txt` change together). `public/llms.txt` is a hand-written summary of the site for AI crawlers: update it when services, the project or contact data change.
- **Legal pages** — `/politica-de-privacidade` and `/termos-de-uso` use `components/layout/legal-page.tsx` (header band, prose, footer). Routes are listed in `legalLinks` (`site.ts`), which feeds the footer and the sitemap. Update the `updated` date when the text changes. Menu anchors are `/#section` so they work from these pages.
- **Images** — `images.unoptimized` is on in `next.config.ts`: `/_next/image` returns 404 under the Vercel `services` deploy. Add raster images already sized and in WebP.
- **Projects** — the Projetos section is data-driven from `src/lib/projects.ts` (media: `image`, `video` or `flow`); the gallery arrows and the list of other projects appear only when there is more than one item.
- **Static assets** — SVGs exported from Figma live in `apps/web/public/brand/` and render via `next/image` (`public/` is excluded from Biome). Section labels are terminal paths (`SectionLabel path='...'`), framed panels use `CornerFrame`, light panels can use the `bg-hatch` utility (inside `cn`, tailwind-merge drops a `bg-[color]` that sits next to `bg-hatch`: set the panel colour with `[background-color:…]`).
- **`packages/ui`** (`@monocode-landing/ui`) — shadcn primitives exported as source (no build step): `@monocode-landing/ui/components/<name>`, `/lib/utils`, `/globals.css`. `apps/web/tsconfig.json` maps these paths to `packages/ui/src`. `Button` has extra `pill` / `pill-lg` sizes for the site CTAs.
- **shadcn style is `base-lyra`** — components are built on `@base-ui/react`, not Radix (use `render={<a … />}` + `nativeButton={false}` for link buttons). Add shared primitives with `pnpm dlx shadcn@latest add <name> -c packages/ui`.
- **Styling** — Tailwind v4 (CSS-first). Palette tokens and shadcn variables are in `packages/ui/src/styles/globals.css`, in a 60-30-10 proportion: 60 paper (`soft` for the ground of light sections, `paper` for cards and the Sobre section), 30 brand dark green (`move`, `move-deep`: hero, method, closing) and 10 accents (`lime` only on dark surfaces: the dark green brand blocks and the `ink` / `ink-deep` panels, such as the selected front and situation, the steps panel, the gallery arrows and the back-to-top button; never on paper; `orange` for human approval and the illustration highlight). On light sections text is `ink` (a neutral near-black), support text is `ink-soft` and dark panels are `ink-deep`: green stays in the dark brand blocks, so do not add green to text, tints or illustrations on light sections. `ochre` and `petrol` are support colours used only inside elements (actor chips, illustration bases), never as a section background or text. Other roles: `panel` (illustration panels), `tag` (Soluções tags), `numeral` (big section numbers), `line`. Use the tokens instead of fixed hex values. Interface elements (front selector, steps panel, method cards, comparison bars, flow cards) have light corners (`rounded-lg` 6px, `rounded-md` 4px); frames with corner marks, the photo and section bands stay square. The hero background takes hex props, so `components/layout/backgrounds.tsx` repeats the `lime`, `move` and `orange` values. Light theme only; `.dark` is never applied. Fonts: Manrope (`font-sans`) and Geist Mono (`font-mono`) via `next/font` in `layout.tsx`.
- **Analytics** — Cloudflare Web Analytics, cookieless. The site is not proxied by Cloudflare (DNS only), so the beacon is a plain `<script>` in `layout.tsx`, rendered only when `CLOUDFLARE_BEACON_TOKEN` is set. The token is public and lives only in Vercel's Production environment, so previews and local dev measure nothing (Cloudflare also rejects other hostnames). The privacy policy describes what is measured: change both together.
- **Env vars** — managed by Varlock. Declare in `apps/web/.env.schema`, regenerate, then import `ENV` from `@/env`. `src/env.ts` is generated; never edit it.
- **Dependency versions** — shared deps are pinned in the `catalog:` of `pnpm-workspace.yaml`; use `catalog:` when adding one of them.

## Code Style (Biome)

Tabs, single quotes (including JSX attributes), no semicolons, `as-needed` arrow parens, ES5 trailing commas. Tailwind classes inside `cn`/`cva`/`clsx` are auto-sorted (`useSortedClasses`).
